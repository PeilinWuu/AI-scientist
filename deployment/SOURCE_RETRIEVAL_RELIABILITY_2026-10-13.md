# 资料检索与阅读体验修复记录

## 范围与参考

在原有固定科研工作流和 Qwen 配置上修复办公室盆栽实测暴露的问题，没有替换模型，没有引入额外付费检索服务，没有修改历史失败记录，也没有把本次续跑包装为最终科研验收。

查阅的实现与产品资料：

- [LangChain Open Deep Research 实现](https://github.com/langchain-ai/open_deep_research/blob/main/src/open_deep_research/utils.py)：并发查询、按 URL 去重、原始内容与来源绑定、带超时的处理。借鉴其分层和来源绑定思路，未移植整个框架。
- [Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search) 与 [Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)：检索与页面提取是不同能力。没有配置或调用 Tavily 服务。
- [百炼联网搜索文档](https://www.alibabacloud.com/help/en/model-studio/web-search)：Responses 搜索来源可能只有链接；不能假定每个来源都有论文摘要。当前解析同时保留工具来源和消息引用中的元数据。

## 已落地修改

| 原问题 | 修改 | 验证 |
| --- | --- | --- |
| source_id 与 URL 冲突时悄悄读取旧网页 | 冲突显式拒绝；允许模型跟进已读页面明确出现的 HTTPS 链接，独立登记来源；仍经过公共地址与重定向安全检查 | 错配、未发现链接、私网地址回归；真实读取 Nature 原页面 |
| 搜索只有 URL，缺标题与摘要 | 最多并行补取前 5 个候选缺失的网页标题/开头预览；缓存原文；明确不是论文摘要、不是已经完成阅读 | 真实搜索 5 个候选中 3 个取得预览，2 个失败保留；后续读取复用缓存 |
| 工具标题把行动意图当成实际结果 | 分离意图、请求地址、实际地址；显示执行中、失败、无新增内容等状态 | 单元测试、前端续跑 |
| 重复读缓存仍算进展 | 按已读区间计算新增字符，重叠部分不计；重复返回不重置无进展判断 | 首次、重复、部分重叠范围回归 |
| 长等待不透明 | 区分工具正在工作与模型等待正文，保留耗时与暂停入口 | 前端看到搜索、阅读和整理动作分别显示；没有声称解决提供商延迟 |
| 中文标点污染裸 URL | 展示层规范裸链接，不改模型原始保存文本；保留规范 Markdown 链接和代码 | 标点、括号、代码、幂等性测试；旧 Nature 链接在页面正确显示 |
| 主页面冗长，内部术语混入回答 | 阶段结果前默认只展开最近 3 条；提示模型少重复目标、用自然语言、不要把模式标签说成已完成系统综述 | 前端检查；模型措辞仍存在波动，不保证提示词完全消除重复 |
| 实测新增：待修订阅读草稿重复作为阶段结果展示 | 同一原文不重复输出；阅读草稿明确标注非最终结果，资料提案需修订时提示当前状态 | 新增回归测试；重启前端加载最新代码 |

预览只是网页开头的原文节选，可能含导航内容；不是自动生成的科研摘要。选源、阅读判断和研究结论仍由 Qwen 处理。访问失败保留失败，不生成虚假摘要来填空。
