# 研究者前端体验记录（2026-10-10）

## 范围与方法

以研究者身份通过 Streamlit 前端新建并推进独立项目，不通过直接修改项目状态或替换模型产出来促成成功。运行记录与源码仅作只读核对。此次评估不修改应用代码。

- 项目：`project_ffbba92234d946e6b51fb2a5186eda43`
- 问题：小样本、低成功率时，二项比例 95% Wald 与 Wilson 置信区间的覆盖率和平均宽度如何？
- 要求：查阅可信资料；n=10/30/100、p=0.01/0.05/0.5，每格至少 20000 次蒙特卡洛重复，固定种子、报告模拟误差、明确 Wald 截断策略；输出图表、CSV、代码与结论。
- 采用新问题而非现有 Iris、阻尼或指数衰减项目；真实模型调用，不使用测试替身。

## 操作记录（北京时间）

1. 19:20 展开“新建或加载其他研究项目”，填入问题和补充约束；不上传虚构观测数据，保持“仅生成研究方案”未勾选、辅助资料审查模式。
2. 点击“创建研究项目”，生成上述项目 ID。
3. 点击“运行下一阶段”：仅由 INTAKE 切换到 QUESTION_FORMULATION，无模型调用。
4. 再次点击“运行下一阶段”：开始 Qwen 问题形式化。
5. 问题形式化真实 Qwen 调用 248 秒，方法选择 172 秒；随后分别点击下一阶段完成领域判断、资料需求提案。保留了全部主要研究约束。
6. 19:34 审阅 Qwen 的资料需求，允许公开网络，背景动作预算 24、项目调用上限 120。批准后还需再点“运行下一阶段”。复选框鼠标点击在本次自动化中未生效，聚焦后按空格有效；尚不能认定是应用本身缺陷。
7. 19:35 Qwen 先通过 Crossref 找论文，再读 Project Euclid；识别反爬页面后主动改搜公开替代版本。真实搜索返回 5 个新候选。
8. 19:36 下一次行动输出含额外字段 `based_on`，触发 `BackgroundAction` 的 `extra_forbidden` 校验，整个阶段失败。打开“错误详情 / 调试信息”才看见真正原因；点击“重试本阶段”恢复尝试，未修改后台状态。
9. 第一次重试先遇到在线 PDF 不支持，切换 arXiv HTML 后读取成功；后续分页返回空文本，然后再次发生 `based_on` 格式错误。通过“要求补查、纠正或重新判断资料需求”填写意见，不勾选重建依据，点击“提交意见”；只读检查确认已持久化到 feedback，再点“重试本阶段”。
10. 19:42 后继续搜读，遇到 PMC 反爬、Wikipedia DNS 失败后转向另一个 arXiv HTML。没有将外部页面挑战绕过或将失败伪装为论文内容。
11. 19:44–19:50 模型对同一篇 2025 年预印本连续评估失败：来源 ID 错误与摘录不匹配交替发生。通过“运行下一阶段”继续新一批，模型最终自行修正并完成评估；未再人工替它改摘录。失败摘录把不连续原文用省略号拼接，验证拒绝有据可查。
12. 19:52 模型提出背景阶段结束，将模拟明确列为后续工作，进入独立核查。
13. 19:55 阅读来源摘要、摘录、局限及独立核查；采用已读 2025 年 arXiv 预印本作为有限的方法背景，点击“确认研究依据并进入主张映射”，再点“运行下一阶段”。不是认可预印本全部结论，也不等于完成模拟。
14. 19:57 主张映射完成，形成 4 条主张（2 条有文献支持、2 条待判断）；点击下一阶段生成假设，同时前端打开“主张与证据”检查内容。
15. 20:03 假设生成完成（实际调用约 281 秒）；HYP-003 将错误进一步写成“截断提高覆盖率”。继续方法细化、研究设计（约 284 秒）、分析方案、复现性与独立审查。
16. 20:18 起的独立审查最终批准，未发现 HYP-003 数学错误；提及成对差异误差和证据字段矛盾为非阻断建议。研究者不直接批准，在“请求修订”选择“假设”，要求修正截断不变量、同样本配对比较和精确二项覆盖校验。
17. 20:27 点击“提交修订请求”，状态回到假设阶段，之后点“运行下一阶段”；不改项目 JSON、不替模型生成假设。
18. 核查发现 hypothesis_scientist 的 payload 不含 revision_feedback，BaseResearchAgent 也不统一注入。新假设虽不再声称截断提高覆盖率，却没有要求中的逐次不变量或精确校验；不能把措辞改善当作执行人工意见的证据。继续方法、设计、分析链路以检验执行。
19. 二次方案审查通过，研究者审阅后批准方案进入计算。21:00 点击“生成计算计划与代码”，等待真实 Qwen 生成；未重复发起任务或切换模型。
20. 代码生成等待二十多分钟后返回，模型计数由 39 增至 41。前端展开 Python 代码，因大段代码显示截断，辅助只读检查同一持久化代码。发现真正模拟逻辑与预写结论混合、导出源码是占位文件；仅为诊断产品行为批准隔离运行，不认可文字结论为科学验收。
21. 隔离运行成功，run `d6edfacdfbf34f4fa688a40aee2c3838`，耗时 1411 ms。真实 CSV 有 9 行，每行 M=20000，seed=20260214，包含覆盖率、宽度及标准误。最小 Wald 覆盖率 0.0953，最小 Wilson 覆盖率 0.9047。
22. 独立只读审计（不是项目生成结果）：用二项 PMF 求和核对 18 个覆盖率，最大差异约 3.12 个报告标准误。查看 PNG 确认中文字形缺失。未修改任何科研产物。
23. 21:35 左右模型结果评估返回 decision=stop、addresses_question=true，正确识别占位代码、字体、缺失原始 Wald 指标及结论夸大，但只列为局限而未要求修复；同时错误声称未实际查阅外部资料。研究者继续“分析实验结果”再“独立复审”，检查后续能否要求补齐。

## 已观察的问题（持续更新，未完成即不宣称全流程通过）

- 首次创建后，页面上方短暂仍显示旧问题，下面状态已是新项目；下次重绘才一致。应创建后立即刷新统一项目上下文。
- 开始研究需要两个同名按钮动作，第一步只是状态迁移。应提供“开始研究”一次完成必要初始化。
- 问题形式化等待时提示“包含联网搜索的背景研究可能需要几分钟”，与当前动作不对应；未显示已等待多久、正在调用哪个角色/模型，也没有页面内任务取消按钮（只有 Streamlit Stop）。
- 研究尚未开始就展示证据覆盖率 0.0、假设完整度 0.0、审查最低评分 0.0，容易把“尚未评估”读成质量差。
- 同页将“经人工审批的隔离 Python 科研计算”列为可用，却把“受控 Python 分析沙箱（实验性）”列为尚未接入，普通用户难以区分。
- Qwen 多返回一个行动元数据字段 `based_on` 就终止整个背景阶段，而非把校验反馈交回模型修复。严格验证动作参数是必要的，但可增加有界结构修复，不应将非安全关键的格式修复交给普通用户。
- 上述结构错误被归类显示为“联网证据检索未成功”，与已经成功的搜索记录矛盾。应说明哪个子步骤失败、哪些工作保留、重试会从哪里继续。
- 读取到反爬页面在动作列表仍显示“读取原文 · 已完成”，虽然模型正确识别了内容问题。工具 HTTP 完成与读到论文正文应区分。
- 论文全文缓存截断于 24000 字符后，请求 offset=24000 返回空文本但仍显示成功。模型知道需要继续阅读，却没有真正取到后文的工具路径。应提供清晰分页边界和全文提取能力。
- “提交意见”成功后输入框未清空、无显著提交回执。用户现场追问是否点击，后台 feedback 已保存。这是直接观察到的操作信心问题，应显示提交时间、意见版本及是否已被模型使用。
- 工具反复失败没有短路或针对性诊断：同一来源反复评估，ID 拼写和摘录错误交替发生。应以短且稳定的工具引用、明确字段反馈、连续失败阈值和模型重新规划减少盲目重试，不能简单关闭真实引用校验。
- 候选书目中包含撤稿通知；模型未采用它，但未筛选的候选与已读推荐混排，增加人工浏览负担。应分为“已读推荐／待查线索／排除或访问失败”，不要仅凭标题决定科研价值。
- 采用建议将作者机构、资助和经典引用作为“方法严谨、可信度高”的主要理由，未清楚区分预印本与同行评审；独立核查声称成功读到 HTML 全文，但实际读取有截断。需要显式传递阅读范围，核查结论不应超出工具事实。
- 前端显示 26/120 次调用时，后台 attempted=28、successful=26、failed=2、fallback=3；数字含义不直观，用户无法据此判断实际请求开销。
- 主张页写“Wald 截断至 [0,1] 会改变其实际覆盖率和平均宽度”（尚未判断）。在真实 p∈[0,1]、原区间上下限有序时，截断保留包含事件，覆盖率不变，只有宽度可能变。这是应由推理或检验发现的科学性错误，不能因流程完成而忽略；观察后续审查是否捕获。
- 后续假设、设计与分析沿用上述错误，独立审查仍批准。复现性与方法评分不应替代基本数学审查；应明确每条假设的来源、可证伪检查与反例验证，而不是多角色重复同一前提。
- “研究设计”页极长，大量小节仅叫“其他说明”，包含未翻译的内部工具标识。主界面缺少必做项、可选项与待决策项的摘要。
- 高优先级：人工“请求修订”保存 revision_feedback 并回退，但假设/方法/设计/分析角色未接收该字段；只有 research_director 明确读取。界面接受反馈不等于目标模型获得反馈。应统一传入结构化修订任务并核验每项要求的落实，保留原文与修改差异。
- 计算代码生成 payload 仅含问题、约束、设计、分析、数据与种子，未直接包含复现工程师与独立审查建议。前面审查中的具体要求不保证进入执行上下文。
- 代码生成等待提示仍写“等待实验执行”并附联网提示；在超过 6 分钟时也没有阶段性响应、已耗时或取消生成入口。需要区分代码生成、审批、沙箱运行、结果分析。
- 计算科研轮次在源码中硬限为 2，超过要求新建项目。建议将资源限制与科学停止条件分开，由模型提出后续实验、用户审批追加预算，保留同项目的连续证据链。
- 高优先级：生成代码在模拟前固定 conclusion.txt 的文字，不根据 df 构造结论，含“保证推断有效”“绝对禁止”等过强表述。数值模拟真实不等于文本报告真实基于结果。
- 高优先级：生成的 simulation_code.py 只有 196 字节，占位语句不可独立复现；应用实际 program.py 有保存，但“导出的源码文件”名不副实。应直接导出受批准且执行的代码及环境，不让模型编造源码副本。
- 承诺的 Wald 未截断覆盖率/宽度未写入 CSV，配对差异误差与精确核验亦未实现；validation_checks 是自然语言清单，代码缺少对应断言。应核对计划到执行的逐项覆盖，不能只看结果 JSON 存在。
- 数值模拟只需 1.4 秒，代码生成等待二十多分钟；模型分析阶段页面仍写“正在隔离环境中计算”，无法区分已执行与正在解释。
- 图像中文字体缺失，标题、轴和图例出现方框。生成计划/验证项改为英文，与中文问题和前面工作流不一致。
- 执行后模型能识别上述缺陷却决定 stop。应把用户承诺的交付物完整性与核心科学结论分开验收，不能把漏交源码/指标一概降级为局限。
- 执行后评估误称未检索资料，与此前已采用 EVD-001 矛盾。角色上下文必须共享“已读取/已采用/未完成”的实际状态，而非从当前窄 payload 猜测整个项目历史。
