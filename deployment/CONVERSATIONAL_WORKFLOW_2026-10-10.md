# 固定科研流程中的 Qwen 原始回答与可靠性改造

## 产品方向

保留问题、背景、假设、方法、设计、执行、分析、复审及报告阶段。阶段约束规定职责和权限，不再用程序模板替代模型给研究者的回答。没有恢复独立自主工作台，也没有删除旧项目或替人审批。

同一次 Qwen 调用同时产生公开回答与后台控制数据：

- `public_response` 是模型直接写出的自然语言 / Markdown，不强制章节或长度；流式显示，历史可折叠。
- `human_input_request` 是模型现场提出的必要问题。它不等于联网、执行代码或科研结论的批准。
- 后台角色、工具参数和结构化产物仍严格验证；不会把任意文字当可执行命令。
- 不读取或展示提供商 `reasoning_content`，不把公开解释冒充私有思维链。无效、未完成调用的文本标为草稿，不作为执行事实。
- 真实提供商响应缺少公开字段时进入有界格式修复，不使用伪造的模板回答填充。

## 本次实现

### 对话与连续推进

- “继续研究，直到需要我操作”在固定状态机中衔接无须新增授权的阶段。
- 必要追问保留原阶段，只保存草案；回答后同阶段重新处理。网络范围、资料采用、科研方案、代码版本等原有审批仍停下。
- “当前阶段结束后暂停”是协作式暂停，不声称撤销已发出的 API 请求。
- 任务记录保存逐调用公开文字、角色、模型、时间和提供商响应 ID；页面明确区分模型原文与系统 / 工具事件。
- 后台任务活动期间拒绝并发项目修改，防止刚提交的回答被工作线程旧状态覆盖。

### 科研上下文与反馈

- 所有普通角色与计算阶段共享有界的原问题、约束、人工意见、问答、研究依据、真实阅读范围、审查要求和执行摘要。
- 不无限复制完整历史；已省略、已截断、只读节选均明确标注。
- 反馈必须回应，但模型应质疑错误的人工科学命题；“已收到”不等于“已采纳或验证”。

### 实际计算与修订

- 评估读取真实运行的 CSV / 文本预览，校验路径、文件大小和哈希；不再仅凭文件名猜测结果。
- 平台登记实际执行的 `program.py` 为权威源码，可从前端选择查看和下载，不依赖模型另写源码副本。
- 分别记录运行、科学充分性、交付完整性；文件可读与哈希正确不等于科学结论正确。
- 修订支持 `execution_code`、`result_table`、`figure`、`reproducibility_bundle`。只有人类批准的批次才能解除上一轮 stop / 默认两轮限制，修改后的代码仍单独审批。
- 修订产物用实际代码、运行、表格内容及原完成标准核验，不能以新计划替代真实修复。交付缺损不能发布成完成。
- 评估提问或失败后保存成功执行的检查点；回答后只续评，不重复执行。原代码、输入或产物变化则拒绝复用旧结果。
- 审计区分运行器提供的种子与代码内实际选择的种子；未验证时明确 `code_seed_verified=false`。

### 背景阅读

- 统一行动协议 `observation_ids`；格式错误最多一次模型修复，修复请求仍需校验。
- 支持 S1 等短来源编号，内部仍使用稳定来源 ID。
- 背景全文缓存最多 20 万字符，每次向模型分页提供最多 1.2 万字符；记录已读范围、下一页和截断原因。
- 越界不再返回空串成功；典型短验证码 / 反爬页明确读取失败，不视为论文正文。
- 来源采用校验提供具体错误，保留引用必须来自已读原文的限制。

## 前端复现

1. 使用既有 `.env` 启动后端及 Streamlit；真实计算仍需 namespace 环境和 `AI_SCIENTIST_ENABLE_COMPUTATION=1`。
2. 创建问题，例如：“研究异常值怎样影响均值和中位数，尚未决定真实数据还是数学模拟，请先问我。”
3. 点击“继续研究，直到需要我操作”。查看“与 Qwen 一起研究”的原始回答、流式草稿及调用凭据。
4. 模型请求选择时，研究暂停在原阶段；在“你的回答”中说明选择后提交，再继续研究。
5. 检查回答是否影响后续问题定义，而不是只看提交回执。
6. 需要网络、采用资料、批准研究或执行代码时仍使用真实审批控件；不得以聊天回答代替授权。
7. 如计算已成功、结果评估尚待补充，使用“继续评估已有结果”，不重新执行。
8. 在计算产物选择器查看真实 CSV、文本、PNG 或实际 `program.py`。审计 JSON 默认只在开发者模式中展示。
