## 真实 Qwen 验收项目（可在前端“加载已有项目 ID”打开）

### 文献核查：`project_7d615373362f4723b75a1284e1a18155`

问题限定为 SciPy 官方 ttest_ind 文档中等方差与 Welch 检验的适用依据和限制。
系统实际执行了联网搜索、原文读取、来源评估、报告生成及独立模型复审。
最终状态 `completed`，最后一次复审 `accept`、`addresses_question=true`、`issues=[]`。
原固定阶段仍是 INTAKE：它没有被伪装成固定阶段流程全部执行。

并非无人干预一次成功：初始过程遇到模型猜测链接的 404、额外域名被安全规则阻断、
复审 API 超时；人工收紧研究范围后得到首版报告。复审模型还曾把当前日期记错，
随后加入可信系统时间；报告参数也曾漏字段，随后加入工具参数嵌套校验。
通过补充反馈、重新提交后，最终报告复审通过。历史报告、失败与反馈均保留。

报告明确只有一份官方 API 文档作为证据，不把文档中的示例数字称为本项目实测。
这验证了一个小型方法学文献核查闭环，不等价于新科研发现、完整系统综述或跨学科能力。

首次生成曾把输出名写成 `/output/...`，严格校验拒绝后才生成合规方案。
早先超时的另一个数值验收项目 `project_0c7cfe70ebf343dfa5bd2400f25ca751` 也保留。

## 本次修复的可靠性问题

1. 科学绘图字体缓存与结果文件共用 64 项上限：现保留输出 64 项、另设临时缓存 256 项，
   共用 32 MiB，总预算在运行中和结束后均检查；只读挂载公共字体配置/缓存。
2. 启动健康检查只导入库，漏掉绘图失败：现在实际生成 PNG。
3. 导入 API 即恢复“遗留任务”，导致测试误伤 live job：改为服务生命周期启动恢复，
   pytest 全局使用临时项目目录。
4. Qwen 请求没有明确思考预算导致长时间消耗/超时：自主工作台限制输出和思考预算，
   保留实际参数回执；不改变原有固定阶段配置。
5. 工具 arguments 内部未在结构化边界校验：现在嵌套校验，最多一次显式预算内格式修复。
6. 页面加载其他终端创建的项目看不到 active job：项目 GET 动态附加 active_job_id；
   前端接管轮询，研究期间也刷新行动进度。
