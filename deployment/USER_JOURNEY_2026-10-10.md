# 固定科研工作流：单一操作入口

## 设计依据

普通用户只需要知道：我在研究什么、目前做到哪里、现在是否需要我操作、结果在哪里。

旧页面的“继续研究，直到需要我操作”和“运行下一阶段”控制的是同一个项目。前者连续推进，后者单步推进；后端互斥避免并发写入，但界面用了不同的忙碌判断，失败后的可操作性和执行阶段行为不一致。另有计算计划生成入口重复，运行状态与人工审核又分散在很长的页面中。

本次保留原有固定科研工作流，统一用户入口，不新增另一套自主工作台。界面提示只解释操作和真实状态，不代替 Qwen 的研究判断。

## 人可以按顺序复现的使用路径

1. 打开 `http://127.0.0.1:8501/`。填写“科学问题”和可选附件、约束，点击“创建研究项目”。创建只保存项目，便于先核对输入，不会自动消耗模型额度。
2. 核对顶部“当前研究问题”，点击“当前进展与下一步”里的“开始研究”。已有项目则显示“继续研究”。无需逐阶段点击。
3. 在“研究对话”中阅读 Qwen 的公开回答。运行期间，同一操作区显示当前动作和耗时；可点“当前阶段结束后暂停”。这是协作式暂停，不会强行取消已发出的模型调用。
4. 若 Qwen 提出必要问题，顶部操作区替换为问题与输入框。填写回答，点击“提交回答并继续研究”；回答保存后从暂停处继续，不需要再去另一个位置寻找启动按钮。
5. 若需要资料与工具授权，顶部直接显示审核表。审阅模型提出的需求；是否联网由自己勾选。点击“批准工具范围并继续研究”。到资料采用环节，再核对实际来源并点击“确认研究依据并继续研究”。没有资料时，仅在模型提出的依据允许时确认不采用外部资料，不把无来源文字变成证据。
6. 若独立审查提出问题，在同一区域逐项决定处理方式，点击“确认修订计划并开始修订”。最终方案审核时，先到“资料与成果”核对各项产物，再在顶部勾选已审阅并点击“批准方案并继续研究”。这些操作不会批准后续生成的新代码。
7. 进入执行阶段后，顶部显示当前唯一有效操作：生成计算方案、审阅并批准计算，或补充实际数据。审阅方法、输入、指标、验证规则和代码，明确勾选后才能“批准并执行计算”。已有结果待评估时只显示“继续评估已有结果”，不会重跑计算。
8. 计算完成后，按顶部提示继续分析和复审。计算成功不等于研究通过；出现新的问题仍需处理。绑定的旧示例执行器保留明确的准备与执行确认，不会被连续推进偷偷启动。
9. 流程完成后，点击“查看研究成果”，进入“资料与成果”，先看到结论、局限与报告下载，再查看实际计算产物和各阶段文档。它不表示科学结论已经得到外部独立证明。
10. 出错时仍在顶部查看原因并恢复。普通模型失败保留“重试当前研究阶段”；缺少计算输入可以补齐后重新生成方案，仍需重新审批代码。被取消或整体失败的项目不会通过继续按钮自动复活。

## 页面分工

- 当前进展与下一步：唯一正常推进、提问、审批和恢复区域。
- 研究对话：Qwen 原始公开回答与已保存的用户补充；不展示私有思维链。
- 资料与成果：附件、真实计算结果、研究方案、审查及报告。历史计算记录只读，不再放置重复的代码审批按钮。
- 运行记录：事件、调用计数与运行依据；计数不是费用账单。
- 项目管理：刷新与带确认的取消操作。
- 开发者调试：单阶段运行、原始 JSON 与旧实验性手动分析工具。普通用户不用打开。

## 验证与边界

导航判定由一个无副作用的状态解析器负责；真正的权限、输入指纹、代码版本、产物校验仍由后端负责。仅修复有效审批下的计算输入恢复，不绕过其他人工关卡。

前端回归使用真实 Streamlit AppTest 与内存后端，覆盖重复按钮、提问优先、失败恢复、确切执行确认、评估恢复、切换页面和组件 ID。它验证交互与路由，不替代真实模型或科学结论验收。

实际调用模型为 `qwen3.8-max`，响应 ID 为 `chatcmpl-b65b50e7-3d41-9a70-a7b7-5b9c5eb9d3c9`。Qwen 返回异常值替换位置的必要确认问题后，任务正常停止，顶部显示“回答 Qwen 的问题”和“提交回答并继续研究”，不再出现通用继续按钮。项目仍在方法选择阶段，等待回答；这不是失败，也没有执行模拟。

额外恢复检查包括：断网时不开放重复启动；失败任务刷新最新项目状态后显示真正可恢复的操作；回答或修订决定已经保存而后续排队失败时不要求重复提交；上传入口使用后端接受的上下文类型。
