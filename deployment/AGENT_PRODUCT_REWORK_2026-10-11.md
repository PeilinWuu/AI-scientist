# Agent 与科研产品整改记录

## 目标

固定科研工作流仍是基础；阶段内部由 Qwen 判断、读取真实资料、选择工具和解释结果。用户不应替系统搬运数据、猜按钮、阅读全部内部计划，亦不能因为程序退出成功就被告知研究成立。

## 参考与取舍

- [Codex 官方公开执行架构](https://developers.openai.com/blog/codex-as-a-platform)：任务状态、执行事件、审批和工具结果是模型周围运行系统的职责。借鉴其职责拆分，不声称复刻 Codex 未公开的内部机制，也不把项目切换为 OpenAI 模型。
- [Codex App Server 协议](https://learn.chatgpt.com/docs/app-server)：借鉴持久任务、运行事件和独立审批的产品边界，不直接引入该服务作为 Qwen 后端。
- [OpenHands Software Agent SDK](https://www.openhands.dev/blog/introducing-the-openhands-software-agent-sdk) 与 [公开仓库](https://github.com/OpenHands/software-agent-sdk)：参考工具、工作区、对话状态与运行环境分离。暂不整体迁移框架，避免丢失现有科研审批、来源与历史项目。
- [Anthropic 工作流与 Agent 工程经验](https://www.anthropic.com/engineering/building-effective-agents)：保留可理解的流程，避免为简单任务增加无收益的复杂编排。科研阶段负责科学规范，不能以固定输出模板替代实际行动。
- [Qwen 官方深度思考接口](https://www.alibabacloud.com/help/en/model-studio/deep-thinking)：Qwen 3.7/3.8 部分混合思考型号默认启用思考，thinking_budget 默认可达到模型最大值；显式设置预算，不能把没有公开正文误判为接口没有活动。
- [Streamlit fragments](https://docs.streamlit.io/develop/concepts/architecture/fragments)、[sidebar](https://docs.streamlit.io/develop/api-reference/layout/st.sidebar)、[image](https://docs.streamlit.io/develop/api-reference/media/st.image)：采用已有组件进行任务导航、周期刷新和真实图片预览。

## 耗时诊断与本轮调整

上次气候任务代码生成约 20 分钟，单次 completion_tokens 为 43075；这并不能精确证明其中多少是推理 token，因为旧审计未保留该细分。代码确认此前没有显式 thinking_budget/max_tokens，且仅公开正文改变时推送进度。另有重复上下文、串行规划和错误修订路径带来的等待。

本轮：

- 已知混合 Qwen 型号显式配置思考：科学角色默认 2048 思考预算；资料读取判断等常规角色关闭深度思考；保留项目显式 extra_body 覆盖。并未换成弱模型。
- 输出预算默认 16000，流式累计时间预算默认 300 秒，单次网络等待默认 90 秒。旧 .env 若有长超时，流式请求将取网络等待与累计预算的较小值。流式累计预算在收到片段时检查，静默等待仍由网络超时终止，故不是精确到秒的硬实时总截止；SDK 重试也可能增加总耗时。
- 新增响应活动、片段计数、公开输出字符数与本次调用耗时，不保存或展示私有推理内容。
- 截断输出不能进入代码审批；耗尽输出预算不自动换另一个模型重新花费长调用。
- 公共回答先说本阶段变化，默认简短，不要求重新复述完整研究方案；保留完整模型原文供展开。界面节选明确标注，不冒充模型生成的摘要。
- 后台审查上下文不再携带全部历史代码快照。

这些是可审计的预算与可观测性修复，**尚未通过新一轮真实调用测量提速或质量变化**。复杂科研任务可能需要提高预算，不能以速度替代科学质量。

## 用户操作路径

1. 左侧“＋ 新研究”或按名称搜索、打开历史研究；无须记项目 ID。编号入口保留在折叠的兼容入口。
2. 输入问题/资料，启动固定流程；只在必要信息或授权缺失时停下。
3. 顶部保留原问题，详细约束折叠。已有图表直接显示并可下载；不必挑选内部文件路径。
4. 当前动作区提供对应回答或审批。代码可“退回并保存修改意见”，再生成时模型会收到意见。
5. 模型对话默认显示最新阶段，长回答为标注节选，完整回答和历史记录可展开。
6. 独立审查中的非阻断建议可集中审阅、明确勾选接受为局限，默认不替用户提交接受；其他可选处置折叠。
7. 报告保存为真实的版本化 Markdown，进入复审前生成草稿；生成与科学验收明确分开。可在页面预览/下载。
8. 点击侧栏历史研究后，直接展开名称下的“✎ 重命名”，输入新名称并保存；只改显示名称，不改研究问题和结果。运行中禁止重命名以免与后台快照竞争，需暂停并等待当前任务结束。

## 已实施的流程修复

- 安全检查后的部分输出会保留；缺少预期文件时仍读取 result.json 中的具体错误，供模型修复。错误输出不算成功。
- 失败尝试进入共享上下文。修复提案更改方法、输出或代码时不自动执行，也不丢弃提案；明确进入新审批。
- CSV 注释、空行及明显单行标题作为可追溯的表头推断处理，产生警告，原始字节不改动。
- inspect_asset 对支持的文本型附件分页读取原文件，非文本仍用解析摘要；有大小限制。
- 背景读取返回实际发现的 HTTPS 链接，download_data 只接受已观察到的链接、授权公网、有限文本数据格式和 2 MiB 上限。沿用 DNS 固定、公网校验、TLS、重定向重验；拒绝伪装为数据的 HTML。原字节、来源、时间和哈希存档并登记到计算输入。
- 报告有独立 report 修订目标；先从通过哈希验证的真实计算产物生成报告再复审。旧 analysis_plan 批次明确要求 report.md 时兼容路由至报告，不更改验收标准。
- 人工提供图像核验记录时可交由独立模型验证，无需强制重跑统计；不自动承认图像已被模型看过。
- 修订补修前、背景阶段动作间检查暂停请求。当前在途调用仍不强杀，暂不是全面的调用边界取消机制。
- 主页面不再使用 sleep/rerun 不结束的脚本轮询，改用 fragment 触发刷新，降低旧审批控件残留风险。
