# 固定工作流中的模型主导背景研究

本次实现是第一阶段改造，不是“已拥有任意领域通用科研能力”的验收证明。主入口、人工审查、假设、方法、设计、执行、复审和综合阶段保持原有结构；没有另建自主工作台。

## 已改变的决策边界

- Qwen 先判断外部资料是必需、可选还是不需要，说明缺口、验证计划及背景研究停止条件。程序不按题型或关键词替它判断。
- 人工批准资料需求、网络访问和预算后，Qwen 每次依据实际观察选择搜索、阅读、检查上传资料、评估来源、补查或请求帮助。单批最多 6 个动作；再次运行不会重置总预算。
- 网页搜索必须有提供商实际工具调用记录。HTTP 请求成功、普通模型解释、无来源的回答都不算已搜索。
- Crossref 仅提供书目线索，缺摘要不代表不相关。推荐采用必须来自实际读取文本，并提供可匹配的短摘录、相关性、可信度与局限说明。标题初筛明确标为仅书目信息。
- 正式采用由人决定。必需资料缺失不能自动改成“不需要”。自足问题可人工确认不采用外部文献，但不会生成虚构证据，也不免除后续验证。
- 背景阶段没有计算执行工具。阶段提案先由独立 Qwen 调用对照实际观察核查；不实的“已完成实验/计算”说明应返回修正，再交人工审核。模型核查仍可能出错，不是真实性保证。
- Qwen 原始审查的决策、分数、阻断意见不再被程序改写；程序完整性提示独立保存。新版修订分类与完成标准由模型明确输出，不再由优先级或医学关键词改写。
- 计算代码修复只要改变代码，必须重新批准具体代码版本；方法描述相同不构成自动执行许可。

## 前端复现

1. 打开 `http://127.0.0.1:8501/`。页面顶部始终显示原始研究问题。
2. 新建项目默认启用新版。旧项目仍使用原记录；若尚在背景研究或资料审查阶段，展开“升级当前项目的背景研究方式（保留历史）”，确认后点击“启用模型主导的背景研究”。此操作归档旧状态，不删除历史，不自动采用来源。
3. 点击“运行下一阶段”，直到背景研究提出资料需求。阅读理由、信息缺口、待执行验证与停止条件。
4. 勾选已审阅；按需允许公共网络；检查动作数和项目模型调用总上限。点击“批准依据与工具范围”。批准本身不开始搜索。
5. 点击“运行下一阶段”。观察“实际进展”：行动目的、搜索是否真正执行、读取节选、失败原因、模型判断。单批结束仍停在背景阶段时，可继续下一批；预算用完需重新授权。
6. 到资料审核时，检查推荐的摘要、摘录、相关性、可信度、局限。勾选需要的已读来源，再点击“确认研究依据并进入主张映射”。没有资料且模型认为可不依赖文献时，需要明确勾选不采用外部资料的确认项。
7. 有异议可在“要求补查、纠正或重新判断资料需求”中提交意见。更改资料需求时勾选重新提出依据；旧授权撤销，新提案再次由你审核。
8. 后续仍按原工作流推进。无文献路径中的前提、假设和验证义务不等于实验发现，计算和实验需在后续阶段真正完成。

## 版本、审计与限制

- 前端新项目使用 `research_policy_version: 2`。直接使用旧 API 创建项目仍默认 v1，以兼容旧客户端；需要新版时显式传 2。
- `background_agent` 保留范围版本、输入指纹、人工授权、动作意图、观察、模型评估和采用决定。输入改变使旧授权失效；采用还绑定具体提案 ID。
- `stage_model_decision` 保存结构化决策与提供商响应/模型/请求标识，不保存隐藏思维链或 API key。`stage_action_intent` 先于工具执行写入；中断不能当成成功。失败也计入调用预算。
- `review_policy_findings` 是程序提示，不能冒充模型判断。旧版已经后处理过的历史审查无法还原为原始模型输出，前端明确标识。
- 当前动作上下文携带最近 12 条观察，以及累计来源、评估与人工反馈；完整观察保存在审计记录。长研究的压缩记忆与选择性回读尚未完成。
- 公共 HTTPS 阅读有 URL/DNS/重定向检查、超时和大小上限，不访问内网、不绕过登录或付费墙。当前在线阅读支持 HTML/文本，PDF 可通过现有上传解析流程提供。读取失败由模型决定换来源或求助。
- 网络访问授权是公共网络级别，不是逐域名白名单；输入中的敏感信息应在研究者授权联网前处理。
- 本阶段没有任意本地文件访问、安装软件、实验执行或自我批准权限。执行阶段的更广泛工具循环、长期记忆、多种数据分析工具扩展仍属后续工作。

## 验证命令

```bash
RUN_NAMESPACE_TESTS=1 .venv/bin/pytest -q
.venv/bin/python -m compileall -q src app_streamlit.py
.venv/bin/python -m pip check
git diff --check
```

可选真实 Qwen 测试（消耗本地已配置 API 的额度）：

```bash
.venv/bin/python scripts/verify_model_led_background.py --live --case math
.venv/bin/python scripts/verify_model_led_background.py --live --case source
```

测试创建独立临时目录，并仅对测试夹具执行授权/采用，绝不批准用户项目。它从背景阶段开始，测试到主张映射完成，不代表前端完整科研流程或实验结果通过。命令会输出保留审计记录的位置；若模型要求澄清或预算不足，会真实失败而非硬改成通过。

搜索适配的接口依据：[阿里云 Responses 文档](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-responses)。当前提供商拒绝思考模式与 `tool_choice=required` 同用，因此在模型已经选定搜索后，独立搜索适配请求关闭思考模式并验证真实工具调用；科研决策调用仍使用所配置的 Qwen 模型和思考能力。
